# 06 · 对话设计：状态机、人设与意图

## 6.1 状态机

```
        ┌────────────────────────────────────────────┐
        ▼                                            │
  [IDLE 问候] ──用户开口──▶ [CHAT 陪聊] ◀─────────────┤
                                │                     │
                     检测到点餐意图                     │
                                ▼                     │
                        [MEMORY 查历史订单]            │
                                ▼                     │
                        [RECO 推荐(营养/画像)]          │
                                ▼                     │
                        [COUPON 查活动+自动领券]        │
                                ▼                     │
                        [ORDER 确认→建单→待支付卡片]    │
                                ▼                     │
                        [WAIT 等餐陪聊] ──"我吃完了"──▶ [REPORT 生成报告卡] ──▶ 回 CHAT
```

## 6.2 状态规格（开工前必须补全，否则兜底话术无从实现）

| 状态 | 进入动作（调哪些工具） | 出口条件 | 兜底话术（工具失败时） |
| --- | --- | --- | --- |
| `IDLE` | 无 | 用户开口 | — |
| `CHAT` | 无（纯陪聊） | 检出点餐意图 | — |
| `MEMORY` | `order-list`、`now-time-info` | 拿到历史订单 / 超时 | "麦门信号不太好，先直接给你看菜单？" |
| `RECO` | `query-meals`、`query-meal-detail`、`list-nutrition-foods` | 用户选定 | "菜单没拉到，你直接说想吃啥，我帮你算" |
| `COUPON` | `campaign-calendar`、`available-coupons`、`auto-bind-coupons` | 领券完成 / 无可领 | "券没查到，不影响点单，先走起" |
| `ORDER` | `query-store-coupons`、`calculate-price`、`create-order` | 返回待支付 | "下单没成功，我再说一遍你要的，你用 App 自己点也行" |
| `WAIT` | 无（陪聊） | "我吃完了" | — |
| `REPORT` | 生成报告卡 PNG | 卡片渲染完成 | 报告卡**必须真实生成**，不可降级 |

> ⚠️ 原文档只给了状态图，上表的"进入动作/出口条件/兜底话术"三列尚未展开 —— **这是 Phase 2 的第一项工作**。

## 6.3 人设（`server/dialog/persona.py`）

两版 system prompt，短句口语、主动调用工具制造记忆感、**不下食物结论前先看营养**。

| 模式 | 描述 | 默认？ |
| --- | --- | --- |
| `gentle` | 温柔树洞：接住情绪，轻声安慰，不评判 | ✅ **建议默认**（合规考虑） |
| `sarcastic` | 毒舌麦门信徒：接梗 + 犀利吐槽 | ⚠️ 可选，**须加合规约束** |

### ⚠️ `sarcastic` 模式的强制约束（写进 prompt）

赛事规则禁止"讽刺、贬低麦当劳品牌/产品/形象"。因此：

- ✅ 可以吐槽：老板、需求变更、bug、加班、通勤、甲方
- ❌ **绝对不可吐槽**：麦当劳的餐品、口味、价格、门店、服务、品牌
- ❌ 不可将麦当劳与其他品牌做对比
- ❌ 不可宣扬不健康饮食方式（如"多吃垃圾食品开心就好"）

## 6.4 意图路由（`server/dialog/intents.py`）

- 优先让 **LLM tool calling 自主决策**，状态机只做"阶段约束"，不硬编码意图关键词
- 状态机的作用：限制当前阶段**可用工具集**，减少误调用
- 意图识别失败时 → 保持当前状态 + 主动反问，不要跳状态

## 6.5 打断（barge-in）设计

1. VAD 检测到用户开始说话
2. 立即停止 TTS 播放（`audio.pause()` + 前端丢弃缓冲）
3. 切到收音，送 ASR
4. ⚠️ **回声防护**：TTS 播放期间需做回声消除或播放音量压制，否则 VAD 会被自己的播报误触发
