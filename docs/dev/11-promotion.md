## 11.1 为什么这是最高优先级

赛事规则明确：**排名依据 = GitHub 公开 Star 数，Star 为 0 不进入排行榜，前 100 名才获奖。**

这意味着：

- **功能做得再好，没人 Star 就没有名次、没有奖**
- Star 需要**时间发酵**，最后 3 天才开始推广来不及
- 官方"活动开始前已获得的 Star 亦计入" → **越早公开仓库越有利**
- 同一账号多个项目只取最高 → **只推这一个仓库**

> 🚨 原方案 5 个 Phase 全是开发，完全没有传播动作。这是本方案最大的战略缺口。

## 11.4 README 的"可 Star 化"要点

README 不只是交付物，它是**转化工具**。必须包含：

1. **第一行就是一句话定位 + Slogan**（一个人吃饭，但不孤单）
2. **顶部放 Demo 视频/GIF**（大多数人只看这个就决定要不要 Star）
3. 3 分钟内能看懂的架构图
4. 快速开始（3 条命令跑起来）
5. 真实 MCP 调用示例（证明"真用了 MCP"，也是评分点）
6. 明确的 Star 引导语

## 11.5 标题与叙事建议

- 好标题方向："用麦当劳 MCP 做了个陪你吃饭的 AI 搭子"、"一个人吃饭，但不孤单"
- 叙事主线：**情绪价值（独居打工人的陪伴）> 技术炫技**
- 技术亮点作为第二层：MCP tool-calling + 本地 ASR + 真实下单闭环

## 11.6 ⚠️ 传播时的合规注意

- 不得在宣传中出现与其他快餐品牌的对比
- 不得贬低麦当劳产品/价格
- 不得写成"鼓励多吃快餐"，叙事落在"陪伴"与"知情选择"
- 严禁刷 Star / 机器人 / 多账号（官方明令，可取消资格）
